Building My Studio Site: When the Portfolio Embeds the Client Work

Program Edge went from brand research to a live five-page site in two sessions — with a homepage that embeds the client build, not a screenshot of it.

#portfolio#static-sites#branding#cloudflare#client-work

I needed a home for client work that wasn’t my personal GitHub profile.

Program Edge is a consulting and build studio — custom websites, AI-assisted product work, and the program management depth to ship both. I built it in two sessions with an AI agent in Cursor: brand identity first, then five pages, deploy verification, and a palette refresh — all live on Cloudflare Pages before the second session ended.

The detail I’m proudest of is small: the homepage doesn’t screenshot the client site. It embeds it live.

Research-driven brand, not taste alone

The logo and palette didn’t come from “what looks nice.” They came from documented research:

  • Shape psychology: rounded forms read warmth; overlapping/interlocking shapes are the visual grammar of collaboration; angular structure reads trust
  • Color: Victoria preferred green over safe teal; emerald keeps teal’s trust depth while fitting an organic leaf mark
  • Serendipity: two converging leaves formed a “V” — collaboration, growth, and identity in one mark

We locked decisions in a BRAND.md file: palette, tagline candidates, logo variants, collaboration pillar. Every later page pulled from that source instead of re-debating.

Positioning landed on Building first, Consulting backed by depth — lead with the tangible offer, differentiate on “rare both.”

Pricing for a new practice: no public rate card yet. Outcome packages, engagement models, and budget qualification on the contact form. Value-based beats hourly when you’re still proving the practice.

Static HTML, one CSS file, design tokens that earn their keep

Same pattern as the Center X client site: static HTML, shared styles.css, minimal vanilla JS. No build step. Mobile-first. Cloudflare Pages auto-deploys from main.

The palette refresh proved why tokens matter. Every dark section referenced --navy. Changing three CSS variables — plus warming the on-dark neutrals — moved the entire site from navy to deep ink-green with no per-page edits. One token family, whole-site reskin.

Embed live, don’t screenshot

The homepage features Center X Equine Therapy in a browser-frame mockup with a real scrollable iframe of the deployed client site.

Why iframe beats screenshot:

  • Always current — when the client site updates, the portfolio updates
  • Proves the build is deployed, not a Figma mock
  • More convincing than “I built this” copy alone

Before writing markup, verify framing: a 401 or X-Frame-Options: DENY kills the embed. Center X had HTTP Basic Auth during early preview; once that came off, the iframe worked.

The blog section pulls from my public RSS feed via fetch + parse in vanilla JS — latest post with image, three recent titles. Progressive enhancement: static fallback survives fetch failure. RSS dates format with timeZone: "UTC" or every post reads one day early in US timezones.

Honest portfolio choices

Not everything ships publicly.

A “Peptide” project turned out to be a private, authenticated app with dosing content — not a removable gate. Stripping auth would be both a security action and a reputation risk. It stayed private and came out of the portfolio. Surfaced the conflict instead of “fixing” it.

Same judgment call on a public LLM-backed demo agent: her API key on a public endpoint means cost and abuse surface. That’s a scope call to flag, not make unilaterally. Existing real agents (ToolWitness, the market-risk report) are honest proof without inventing a demo.

The Work page tells Center X through two lenses — product (start-with-user, North Star, business objective) and program (discovery trail, dependencies, critical path). Pulled from real project research, not invented case study fiction.

Deploy verification: trust dig + curl, not the badge

Cloudflare Pages dashboard showed “Verifying” on the apex domain with a scary “up to 48 hours” banner. Meanwhile dig and curl returned 200 with a valid cert.

Lessons from go-live:

  • Cache-bust on a no-build static site. Without bundler hashes, stale styles.css lies in the browser. ?v=YYYYMMDD on asset links plus _headers revalidate for HTML makes “did my change ship?” answerable.
  • Deploy is two clicks, not one. Adding the apex custom domain doesn’t add www — separate entry, then _redirects www→apex has something to redirect.
  • Verify all five routes after push. “Committed” isn’t “live.” I curled every page and grepped deployed CSS for the new --navy: #0f1e17 to confirm the palette actually shipped.

Contact form uses Web3Forms with accessibility labels, honeypot, budget dropdown, AJAX submit, and no-JS fallback.

The loop that closed

Center X credits Program Edge in the footer — “Site built by Program Edge” with a CTA to program-edge.com/contact.

Program Edge embeds Center X on the homepage.

Client work and studio marketing reinforce each other. That’s the model: build something real for someone, it helps them, and it compounds into proof for the next client.

What I’d do differently

Hand off at ~87% context with a HANDOFF.md worked — but I’d generate optimized screenshots earlier. Live embeds are better for the hero; case study cards still need compressed JPEGs (sips on macOS: 3.5MB PNG → 160K JPEG).

iCloud custom-domain email has a known deadlock: skip “add existing addresses” (sends un-receivable verifications), verify via DNS instead, keep Cloudflare Email Routing off so it doesn’t fight iCloud’s MX.
